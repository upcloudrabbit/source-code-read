# Spring Framework 编译与运行流程
> 上次修改：2026-07-25 02:11

## 技术栈与依赖

Spring Framework 7.0.7 是企业级 Java 应用的基础框架，采用 Gradle 多模块构建（`settings.gradle` 聚合 22 个 `spring-*` 子模块及 `framework-*` 辅助模块、独立 `integration-tests` 模块）。主语言为 Java（含 AspectJ `.aj` 切面，如 `spring-aspects`），辅以 Kotlin（协程支持、DSL，源码位于各模块 `src/main/kotlin`）和 Groovy（部分测试）。构建由 Gradle Wrapper（Gradle 9.4.1）驱动，构建逻辑集中在 `buildSrc`（`ConventionsPlugin` 统一装配 `CheckstyleConventions`、`JavaConventions`、`KotlinConventions`、`TestConventions` 及架构检查插件）。

关键构建命令：

```bash
./gradlew build                 # 全量构建（编译 + 测试 + 打包 + 检查）
./gradlew :spring-core:build    # 构建单个模块
./gradlew test                  # 运行全部测试
./gradlew antora                # 生成参考文档站点
./gradlew publishToMavenLocal   # 安装制品到本地 Maven 仓库
```

### 环境要求

- **操作系统**：跨平台（Linux / macOS / Windows；CI 在 `.github/workflows/ci.yml` 覆盖三平台及 JDK 21/25 矩阵，Windows 需开启 `core.longPaths`）。
- **JDK**：JDK 25 用于运行构建与编译（Java Toolchain 强制，见 `JavaConventions.applyToolchainConventions`）；Gradle Toolchain 可自动下载缺失 JDK。`gradle.properties` 中 `org.gradle.jvmargs=-Xmx2048m` 要求构建进程堆内存至少 2 GB。
- **SDKMAN（可选）**：`.sdkmanrc` 指定 `java=25-librca`，启用 `sdkman_auto_env` 后自动切换。
- **磁盘**：完整检出 + 构建缓存约需 2-3 GB（未在当前分析范围内确认精确值，按多模块工程经验估计）。
- **网络**：首次构建需访问 Maven Central（版本含 `-` 时追加 repo.spring.io/milestone，SNAPSHOT 时追加 repo.spring.io/snapshot，见根 `build.gradle` 仓库配置）；本工作区 Wrapper 指向腾讯云镜像 `mirrors.cloud.tencent.com`。

## 编译流程

### 编译环境准备

1. **克隆源码**：`git clone https://github.com/spring-projects/spring-framework.git`（PR 一律基于 `main` 分支，见 `CONTRIBUTING.md`）。
2. **安装/确认 JDK 25**：`sdk env`（使用 SDKMAN 时按 `.sdkmanrc` 自动切换）或自行安装 JDK 25；无需预装 Gradle，`./gradlew` 首次执行会按 `gradle/wrapper/gradle-wrapper.properties` 下载 Gradle 9.4.1。
3. **验证环境**：`./gradlew -version`（确认 JVM 25 与 Gradle 9.4.1）。
4. **了解构建约定**（可选但推荐）：构建逻辑在 `buildSrc` 中——`ConventionsPlugin` 对所有子项目装配 Java/Kotlin/Checkstyle/测试约定；`JavaConventions` 设定工具链 25、字节码 release 17，主源码编译参数含 `-Werror`（警告即错误）与一组 `-Xlint`，测试源码放宽部分 lint；`KotlinConventions` 固定 Kotlin 2.2 API、`jvmTarget=17`、`-Werror`。

### 编译步骤

1. **全量构建**：`./gradlew build`
   做什么：编译全部模块的 main/test 源码（Java + Kotlin + AspectJ + Groovy 测试），运行 Checkstyle、架构检查（`ArchitecturePlugin`）、全部单元测试，并打出各模块 JAR。`gradle.properties` 已开启 `org.gradle.caching=true` 与 `org.gradle.parallel=true`，增量与并行构建默认生效。
2. **只编译不测试**：`./gradlew assemble`（全部模块打包）或 `./gradlew compileJava`（仅编译主源码）。
3. **单模块构建**：`./gradlew :spring-core:build`（或 `:spring-beans:build` 等），利用 Gradle 的项目路径定位，只构建该模块及其依赖。
4. **生成参考文档站点**：`./gradlew antora`
   做什么：在 `framework-docs` 模块中执行 Antora 插件（`framework-docs.gradle`），将 `framework-docs/modules/ROOT` 下的 AsciiDoc 源渲染为 HTML 站点（见 `CONTRIBUTING.md` 的 Reference Docs 一节）。
5. **生成聚合 Javadoc**：`./gradlew :framework-api:javadoc`（聚合 API 文档，另启用 `reference` 级 doclint 检查）。
6. **发布到本地仓库**：`./gradlew publishToMavenLocal`，将各模块 JAR（含 sources/javadoc 分类器，见 `gradle/spring-module.gradle` 的 `sourcesJar`/`javadocJar`）安装到 `~/.m2/repository`，供本地其他工程以 `org.springframework:spring-core:7.0.7` 等坐标引用。
7. **微基准（可选）**：各模块 `src/jmh` 下的 JMH 基准由 `me.champeau.jmh` 插件编译，运行 `./gradlew :spring-core:jmh`。

### 编译产物说明

- **各模块 JAR**：`<模块>/build/libs/<模块>-7.0.7.jar`，附 `-sources.jar`、`-javadoc.jar`（`spring-module.gradle` 注册 `sourcesJar`/`javadocJar`）。JAR 清单写入 `Implementation-Title/Version`、`Automatic-Module-Name`（JPMS）并在 `META-INF` 注入 license/notice。部分模块为**多版本 JAR**（如 `spring-core` 的 java21 源码集由 `buildSrc/multirelease` 约定处理，`JavaConventions.setJavaRelease` 按任务名选择更高的 `--release` 版本）。
- **测试/夹具类**：`<模块>/build/classes/`（main、test、testFixtures 分开输出）。
- **JMH 基准 JAR**：`<模块>/build/libs/<模块>-7.0.7-jmh.jar`。
- **文档站点**：`framework-docs/build/site/index.html`（Antora 产物）。
- **本地 Maven 制品**：`~/.m2/repository/org/springframework/...`（`publishToMavenLocal` 后）。
- **构建扫描**：`settings.gradle` 集成 Develocity，构建后 `build/build-scan-uri.txt` 记录扫描链接。

## 运行流程

Spring Framework 是**框架类库**，没有独立可运行的入口（无 main 函数、无服务进程、无 Docker 镜像）。"运行"即把构建产物作为依赖引入使用方应用。

### 本地运行

1. **安装制品**：在框架源码根目录执行 `./gradlew publishToMavenLocal`（或 `publishToMavenLocal -x test` 跳过测试）。
2. **在使用方工程引用依赖**，例如 Maven：

```xml
<dependency>
  <groupId>org.springframework</groupId>
  <artifactId>spring-context</artifactId>
  <version>7.0.7</version>
</dependency>
```

   或 Gradle（Kotlin DSL）：`implementation("org.springframework:spring-webflux:7.0.7")`。发布坐标对所有 22 个 `spring-*` 模块生效，统一管理可用 `framework-bom`（平台模块）。
3. **运行使用方应用**：由使用方工程自行启动（如 `java -jar`、Servlet 容器部署等），运行期 JDK 要求为 **Java 17+**（发布字节码基线 17）。

### Docker 运行（可选）

不适用：本工程不提供 Dockerfile、docker-compose 或镜像构建任务，无任何容器化产物。

### 运行配置说明

框架本身无启动配置。使用方应用的配置（如 `application.properties`、Bean 定义）属于各模块的运行时特性。构建期可调的运行相关属性：

| 属性/环境变量 | 作用 | 来源 |
|---------------|------|------|
| `org.gradle.caching=true` | 开启构建缓存 | `gradle.properties` |
| `org.gradle.parallel=true` | 并行构建 | `gradle.properties` |
| `org.gradle.jvmargs=-Xmx2048m` | Gradle 守护进程堆内存 | `gradle.properties` |
| `kotlinVersion` / `byteBuddyVersion` | Kotlin 插件与 Byte Buddy agent 版本 | `gradle.properties` |
| `-PtestGroups=...` | 按组过滤测试（传入测试 JVM 系统属性） | `TestConventions` |
| `CI=true` | CI 环境下失败测试自动重试 3 次 | `TestConventions.configureTestRetryPlugin` |

## 测试流程（如适用）

测试框架为 JUnit 6（Jupiter，junit-bom 6.0.3）+ Mockito 5.23.0 + MockK 1.14.5 + AssertJ 3.27.7，由根 `build.gradle` 对所有 Java 项目统一注入测试依赖。`TestConventions` 统一配置测试任务：使用 JUnit Platform；仅匹配 `**/*Tests.class` 与 `**/*Test.class`；系统属性含 `java.awt.headless=true`、Netty 泄漏检测 `paranoid`；JVM 参数含 `--add-opens java.base/java.lang|java.util` 与 `-javaagent:byte-buddy-agent:1.17.6`（Mockito 内联 mock 依赖）。CI（环境变量 `CI=true`）下失败测试重试最多 3 次且重试后通过视为失败（`failOnPassedAfterRetry`）。

### 单元测试

- **测试目录**：各模块 `src/test/java`（Java）、`src/test/kotlin`（Kotlin）、`src/test/groovy`（Groovy，如 spring-beans/spring-context 的部分测试）；公共测试夹具在 `src/testFixtures`。
- **编译测试代码**：`./gradlew :spring-core:compileTestJava`（Kotlin 测试由 `compileTestKotlin` 随 `test` 任务链自动编译）。
- **运行全部单元测试**：`./gradlew test`（所有模块）。
- **运行单模块测试**：`./gradlew :spring-beans:test`。
- **按模式过滤**：`./gradlew :spring-beans:test --tests 'org.springframework.beans.*'`；单类：`--tests 'org.springframework.beans.factory.support.DefaultListableBeanFactoryTests'`。
- **测试报告**：`<模块>/build/reports/tests/test/index.html`；结果 XML 在 `<模块>/build/test-results/test/`。

### 集成测试

- **独立模块 `integration-tests`**（`integration-tests.gradle`）：聚合 spring-aop、spring-beans、spring-context、spring-core、spring-expression、spring-jdbc、spring-orm、spring-test、spring-tx、spring-web 及各模块 testFixtures，额外引入 Hibernate ORM、HSQLDB、AspectJ Weaver、Jakarta 资源/servlet API、kotlinx-coroutines-reactor，用于**跨模块集成测试**（如容器级事务、ORM 整合、运行时提示 agent `runtimehints-agent`）。
- **测试目录**：`integration-tests/src/test/{java,kotlin,resources}`。
- **运行命令**：`./gradlew :integration-tests:test`；过滤同上 `--tests '...'`。
- **CI 编排**：`.github/workflows/ci.yml` 在 Linux/macOS/Windows 与 JDK 21/25 矩阵下执行完整构建（含集成测试）。

### 测试覆盖率（可选）

未在当前分析范围内确认：根 `build.gradle`、`gradle/*.gradle` 与 `buildSrc` 约定插件中均未配置 JaCoCo 或其他覆盖率插件，当前构建不产出覆盖率报告。如需覆盖率，可在使用方或本地临时追加 `jacoco` 插件（属于工程默认之外的扩展）。
